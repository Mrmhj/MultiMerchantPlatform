# cart-service 购物车服务

> 模块文档 · 摩登时代 · 2026-08-02 · Phase 2 Week 10

## 一、概述

| 项 | 值 |
|---|---|
| 端口 | **8007** |
| 数据库 | `MMP_Cart`（CartItems 表） |
| 网关路由 | `/api/cart/**`（直通，无前缀剥离） |
| 鉴权 | 买家 JWT（`[Authorize]` 全接口） |
| 隔离维度 | **买家 UserId**（每买家独立购物车） |

**定位**：购物车是"待结算清单"，商品/价格快照存于条目中，下单以订单实际价为准。

## 二、核心设计

### 实体模型（单表 CartItem）

```
CartItem
 ├─ 归属：UserId（买家隔离）
 ├─ 商品快照：MerchantId/ProductId/SkuId/SkuCode/Spec/UnitPrice
 ├─ 数量：Quantity（1-999，同 SKU 自动合并）
 └─ 选中：IsSelected（默认选中，结算取选中项）
```

### 关键规则

1. **同 SKU 合并**：同一买家加购同一 SKU → 数量相加（上限 999），不产生重复条目
2. **买家隔离**：所有查询/操作按 `UserId` 过滤，他用户无法看到或操作他人购物车
3. **选中合计**：列表返回 `SelectedTotal`（选中项小计之和），供结算页直接使用
4. **快照原则**：条目存商品名/规格/单价快照，与订单一致（订单创建时以订单价为准）

## 三、API 清单

| 方法 | 路径 | 说明 | 鉴权 |
|---|---|---|---|
| POST | `/api/cart/items` | 加入购物车（同 SKU 合并） | ✅ |
| GET | `/api/cart` | 我的购物车（条目 + 选中合计） | ✅ |
| PUT | `/api/cart/items/{id}/quantity` | 修改数量（1-999） | ✅ |
| PUT | `/api/cart/items/{id}/select` | 设置选中/取消 | ✅ |
| DELETE | `/api/cart/items/{id}` | 删除条目 | ✅ |
| DELETE | `/api/cart?onlySelected=true` | 清空（默认只清选中项） | ✅ |

## 四、状态与约束

- 数量范围 1-999（越界抛 `INVALID_QUANTITY`）
- 条目不存在或不属于当前用户 → 404（不泄露他人数据存在性）
- 未登录访问 → 401

## 五、联调验证（2026-08-02 实测）

```
加购 ×1 ✅ → 同 SKU 再加 ×2 → 合并为 3 ✅ → 第二件加购 ✅
列表（2 条目，合计 59.9）✅ → 改量 3→5 ✅ → 取消选中（合计 79.0）✅
买家2 隔离（空购物车）✅ → 删除 ✅ → 清空 ✅ → 网关转发 ✅
```

## 六、已知限制与扩展

- **未接入**：商品删除/下架后购物车条目自动失效提示（Phase 3 补）
- **结算**：前端取选中项直接调 order-service 创建订单（购物车不持有结算流程）
- **限购**：未校验商户/商品状态（上架/库存），下单时由 order/stock 服务把关
